# SC 1.3.1 — Info and Relationships (Level A)

## Intent
Information, structure, and relationships conveyed through visual presentation can be programmatically determined or are available in text — so assistive technologies can understand and convey them.

## Applies to
Headings, lists, tables, form labels, groupings, emphasis, required fields, error states, and any structure conveyed visually.

## Passes when
- Headings use `<h1>`–`<h6>` (not styled `<div>` or `<p>`)
- Lists use `<ul>`, `<ol>`, or `<dl>`
- Data tables use `<th>` with `scope` attributes and `<caption>` where needed
- Form inputs are associated with `<label>` via `for`/`id` pairing or wrapping
- Related inputs are grouped with `<fieldset>` and `<legend>`
- Required fields are indicated programmatically (`required` or `aria-required="true"`)
- Visual emphasis conveyed semantically (`<strong>`, `<em>`) where meaning is intended

## Fails when
- Headings created with CSS-styled `<div>` or `<p>` elements
- Table structure conveyed visually only — no `<th>` or `scope`
- Form labels are placeholder text only
- `<b>` or `<i>` used where semantic meaning is intended (use `<strong>` or `<em>`)
- Visual grouping of form fields has no programmatic equivalent

## Code examples

```html
<!-- Correct: semantic heading -->
<h2>Contact details</h2>

<!-- Incorrect: styled div -->
<div class="heading">Contact details</div>

<!-- Correct: labelled input -->
<label for="email">Email address</label>
<input type="email" id="email">

<!-- Correct: grouped radio buttons -->
<fieldset>
  <legend>Preferred contact method</legend>
  <label><input type="radio" name="contact" value="email"> Email</label>
  <label><input type="radio" name="contact" value="phone"> Phone</label>
</fieldset>

<!-- Correct: data table -->
<table>
  <caption>Q4 Sales by Region</caption>
  <thead>
    <tr>
      <th scope="col">Region</th>
      <th scope="col">Sales</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>North</td>
      <td>$42,000</td>
    </tr>
  </tbody>
</table>
```
