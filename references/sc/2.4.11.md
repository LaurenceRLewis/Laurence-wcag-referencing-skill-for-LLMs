# SC 2.4.11 — Focus Not Obscured (Minimum) (Level AA) ← NEW in WCAG 2.2

## Intent
When a UI component receives keyboard focus, it is not entirely hidden by author-created content — so keyboard users can see where focus is even when sticky or fixed elements are present.

## Passes when
At least part of the focused component is visible — not entirely covered by another element.

## Fails when
- A sticky header completely covers the focused form field when the user tabs down the page
- A cookie consent banner sits directly over the focused Accept/Decline buttons
- A floating chat widget overlaps and entirely covers focused content
- A fixed footer entirely covers a focused element near the bottom of the viewport

## Note
This SC allows *partial* obscuring — the focused element just must not be *entirely* hidden. SC 2.4.12 (AAA) is the stricter version that requires the focused element to be fully visible.

## Common fix
Use `scroll-margin-top` (or `scroll-padding-top` on the scroll container) to offset the scroll position so focused elements appear below sticky headers.

```css
/* Offset focused elements from a sticky header */
:focus {
  scroll-margin-top: 80px; /* height of sticky header */
}
```

## WCAG 2.2 change
NEW in WCAG 2.2 — did not exist in WCAG 2.1.
