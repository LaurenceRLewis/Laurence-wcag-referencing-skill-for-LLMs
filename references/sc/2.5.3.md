# SC 2.5.3 — Label in Name (Level A)

## Intent
For UI components with visible text labels, the accessible name of the component contains the visible label text — so speech input users can activate controls by speaking their visible name.

## Passes when
- A button with visible text "Search" has an accessible name of "Search" (or "Search this site" — starts with the visible text)
- No `aria-label` overrides the visible text with something different

## Fails when
- A button with visible text "Search" has `aria-label="Find"` — speaking "click Search" fails
- A link displays "Buy now" but has `aria-label="Purchase product XYZ"` — speaking "click Buy now" fails

## Rule
The accessible name must *contain* the visible label text. It can be longer (adding context), but it cannot be entirely different.

## Code examples

```html
<!-- Pass: aria-label contains visible text -->
<button aria-label="Search this site">Search</button>

<!-- Fail: aria-label replaces visible text -->
<button aria-label="Find content">Search</button>

<!-- Pass: no aria-label, uses text content -->
<button>Search</button>
```

No change from WCAG 2.1.
