# SC 2.1.2 — No Keyboard Trap (Level A)

## Intent
Keyboard focus is never locked inside a component so that users cannot navigate away using standard keys.

## Passes when
- Users can always navigate away from any component using Tab, Shift+Tab, Arrow keys, or Escape
- Modal dialogs trap focus intentionally but provide Escape or a visible close mechanism to exit

## Fails when
- Focus enters a widget and there is no keyboard mechanism to leave it
- Tab cycles within a component indefinitely with no way out
- A date picker, rich text editor, or embedded map captures focus with no escape route

## Note on intentional focus trapping
Modal dialogs should intentionally trap keyboard focus while open — this is correct and expected behaviour. The trap is acceptable as long as Escape or a close button exits the modal and returns focus to the trigger element. This is not a failure of SC 2.1.2.

## WCAG 2.2 change
No change from WCAG 2.1.
