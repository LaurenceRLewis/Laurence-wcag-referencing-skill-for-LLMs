# SC 3.3.7 — Redundant Entry (Level A) ← NEW in WCAG 2.2

## Intent
Information previously entered by the user that is required again in the same process is auto-populated or available for selection — so users are not required to remember and re-enter the same information.

## Applies to
Multi-step forms and processes: checkout flows, registration wizards, application forms, any task broken into sequential steps.

## Passes when
- Billing address has a "same as shipping address" checkbox that auto-fills from step 1
- User's name entered in step 1 is pre-filled in a confirmation step
- Previously selected options are retained when the user navigates back in a wizard
- Username is pre-filled when creating an account after entering it on a prior screen

## Fails when
- Multi-step checkout requires name and email to be entered again in step 3 despite being entered in step 1
- Address entered earlier in a session must be manually re-entered on a later screen in the same process

## Exceptions
- Re-entry required for security (e.g. "confirm new password")
- CAPTCHA or OTP — inherently single-use
- Previously entered data is no longer valid (expired token)
- Re-entering is essential to the purpose (e.g. a data-entry accuracy training exercise)

## WCAG 2.2 change
NEW in WCAG 2.2 — did not exist in WCAG 2.1.
