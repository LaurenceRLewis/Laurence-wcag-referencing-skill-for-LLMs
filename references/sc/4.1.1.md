# SC 4.1.1 — Parsing (REMOVED in WCAG 2.2)

> **This success criterion was removed in WCAG 2.2 (October 2023) and is no longer testable.**

## What it was
Previously required that HTML be well-formed: unique IDs, correct element nesting, complete start/end tags, and attributes named according to specification.

## Why it was removed
Modern browsers parse and repair malformed HTML consistently and predictably. The variations in how browsers handle invalid markup no longer have a meaningful accessibility impact. Testing against this criterion no longer produced useful results.

## What this means for audits
- **If auditing against WCAG 2.2:** Do not test or report SC 4.1.1. It does not exist in this version.
- **If auditing against WCAG 2.1:** SC 4.1.1 still applies. Test for duplicate IDs, invalid nesting, and malformed markup.

## Still worth fixing
While duplicate IDs and malformed HTML are no longer a WCAG 2.2 conformance issue, they can still cause problems:
- Duplicate IDs break `aria-labelledby` and `aria-describedby` references (which are tested under SC 4.1.2)
- Malformed HTML may cause unexpected rendering in some environments
