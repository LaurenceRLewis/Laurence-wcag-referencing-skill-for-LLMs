# SC 1.4.3 Contrast (Minimum) (Level AA) — Manual Test Pattern

## 1 Overview

**SC:** 1.4.3 — Contrast (Minimum) (Level AA)
**Intent:** Verify that text and images of text have sufficient contrast against their background so that users with moderately low vision can read the content without relying on contrast-enhancing assistive technology.
**Scope of this test:** All text and images of text on the page, including body copy, headings, labels, error messages, placeholder text, navigation, button text, and text in interactive states.

---

## 2 Scope: what to test

Apply these tests to:

- Body text, paragraphs, and headings
- Form labels, hint text, and error messages
- Placeholder text inside form inputs
- Button and link text
- Navigation labels and menu items
- Text inside modal dialogs, tooltips, and popovers
- Dynamically inserted text: notifications, validation messages, live region updates
- Text that changes colour on interaction: hover, focus, active, and visited states
- Images of text (raster or SVG text rendered as an image where the text conveys information)

Do **not** test:

- Logotypes: text that is part of a brand logo or trademark is explicitly exempt
- Decorative text with no informational value (e.g. purely visual background typography)
- Inactive or disabled UI components: text on `disabled` inputs, buttons with `disabled`, or elements with `aria-disabled="true"` is explicitly exempt
- Non-text UI component boundaries and state indicators (covered by SC 1.4.11)
- Captions and subtitles embedded in video (covered by SC 1.2.x)

## 3 Tools required

| Tool | Purpose | Free? |
|------|---------|-------|
| Browser DevTools (Chrome, Edge, or Firefox) | Inspect computed CSS `color`, `background-color`, `font-size`, and `font-weight` to determine the applicable contrast threshold; read colour values for manual input into CCA | Yes |
| TPGi Colour Contrast Analyser (CCA) desktop app | Sample foreground and background colours from the screen using the eyedropper and calculate the contrast ratio | Yes |
| A11y Quick Check browser extension | Run "Colour Contrast" checks to surface potential failures across the page | Yes |
| axe DevTools browser extension (or your preferred automation testing tool) | Automated scan to flag `color-contrast` violations at scale | Yes (core) |
| NVDA + Chrome, Edge, or Firefox (Windows) | Confirm that text announced by the screen reader corresponds to text that also passes contrast requirements | Yes |
| JAWS + Chrome, Edge, or Firefox (Windows) | Secondary screen reader confirmation | No |
| VoiceOver + Safari (macOS / iOS) | Confirm on Apple platforms | Yes (built-in) |

> **Configuration note:** The CCA eyedropper samples the rendered pixel colour. For thin or small text, zoom the browser to 200% before sampling to get a more accurate pixel. Disable forced-colour or high-contrast OS modes before testing — these override author styles and will not reflect the authored contrast ratio. When sampling text over a gradient or image background, sample the background at multiple points along the text baseline and record the worst-case (lowest) contrast ratio found.

## 4 Test steps

Work through every step in sequence. Record a result (Pass / Fail / N/A) for each step.

### Step 1 Run automated and visual checks

**Action:** Open A11y Quick Check and run the "Colour Contrast" check from the extension. Note every element flagged with a warning or failure. Then activate axe DevTools browser extension (or your preferred automation testing tool) and run a full-page scan. Export or note every violation under the `color-contrast` rule. Review each flagged element manually in Steps 2 to 7 before scoring.

**Expected result:** Zero `color-contrast` violations, or each flagged item is confirmed as a false positive (see Section 6) after manual review.

**Fail signal:** Any `color-contrast` violation not subsequently confirmed as a false positive in manual steps.

---

### Step 2 Determine the applicable contrast threshold for each text element

**Action:** Before measuring contrast, determine whether each text element qualifies as large text (3:1 threshold) or normal text (4.5:1 threshold). Open DevTools and inspect the element. In the Computed styles panel, read the `font-size` and `font-weight` values. Apply the following rules:

- **Large text (3:1 applies):** `font-size` is 24px or greater, regardless of weight; **or** `font-size` is 18.67px (approximately 14pt) or greater and `font-weight` is 700 or bold.
- **Normal text (4.5:1 applies):** everything else, including text below 24px that is not bold, and text below 18.67px at any weight.

Record the threshold that applies to each element before measuring.

**Expected result:** Each element is correctly categorised as large or normal text so that the correct threshold is applied in subsequent steps.

**Fail signal:** Applying the 3:1 large-text threshold to text that does not meet the size or weight criteria, which would understate failures.

> **Note:** CSS points and pixels: 18pt = 24px and 14pt = 18.67px at the standard 96 PPI reference. Use computed pixel values from DevTools rather than point values from design files, as user font size preferences can affect rendered size.

---

### Step 3 Check normal text (4.5:1 threshold)

**Action:** For each block of normal-weight text below 24px (and bold text below 18.67px), do the following. Open CCA. Use the eyedropper to sample the text colour (foreground). Then sample the background colour immediately behind the text. Read the contrast ratio in the CCA result panel.

Sample at least the following on each page: one body paragraph, one heading, all form labels, all error messages, all navigation labels, and all button labels that qualify as normal text.

**Expected result:** Every normal text element has a contrast ratio of 4.5:1 or greater against its background.

**Fail signal:** Any normal text element falls below 4.5:1. Common failures: `#767676` on `#ffffff` (4.48:1 — fractionally below the threshold); `#949494` on `#ffffff` (3.03:1); any grey body text on a white card component.

---

### Step 4 Check large text (3:1 threshold)

**Action:** Identify all text elements confirmed as large text in Step 2. For each, use the CCA eyedropper to sample the text colour and background colour. Read the contrast ratio.

**Expected result:** Every large text element has a contrast ratio of 3:1 or greater against its background.

**Fail signal:** Any large text element falls below 3:1. Note that the lower threshold for large text does not justify extremely low contrast — a ratio of 2.8:1 on a large heading is still a failure.

---

### Step 5 Check placeholder text

**Action:** Identify all form inputs that display placeholder text. Focus each input so the placeholder is visible. Use the CCA eyedropper to sample the placeholder text colour against the input background colour. Read the contrast ratio. Determine whether the text is normal or large sized (Step 2) and apply the corresponding threshold.

**Expected result:** Every placeholder text instance meets 4.5:1 (or 3:1 if it qualifies as large text).

**Fail signal:** Placeholder text falls below the applicable threshold. This is a common failure: browser default placeholder styles typically render at approximately `#757575` or lighter, which can fall below 4.5:1 on white or near-white backgrounds.

> **Note:** Placeholder text is not exempt from SC 1.4.3 despite common assumption. The WCAG definition of "text" includes all rendered text regardless of how it is produced. Placeholders that disappear on input are additionally covered by SC 3.3.2 (Labels or Instructions), but their contrast is assessed here.

---

### Step 6 Check text over images, gradients, and variable backgrounds

**Action:** Identify any text that is placed over a non-solid background: a photographic image, a CSS gradient, a translucent overlay, or a pattern. For each, sample the background at a minimum of three points along the text baseline using the CCA eyedropper: at the left edge, centre, and right edge of a representative line of text. Record the contrast ratio at each point. The lowest ratio is the operative result.

For text over a gradient, also sample at the point in the gradient that produces the least contrast with the text colour.

**Expected result:** The worst-case contrast ratio across all sampled background points meets the applicable threshold (4.5:1 for normal text, 3:1 for large text).

**Fail signal:** Any sampled point falls below the applicable threshold. A common failure: white text on a hero image where the image is light in one area; or dark body text over a gradient that transitions from white to a mid-tone colour.

---

### Step 7 Check text in interactive states

**Action:** For all interactive text elements — links, buttons, navigation items, tab labels — check the contrast of the text colour in each applicable visual state by triggering the state and sampling with CCA:

- **Default state:** already covered in Steps 3 and 4.
- **Hover state:** move the cursor over the element and immediately sample using CCA. Do not move the cursor away while sampling.
- **Focus state:** use Tab to move keyboard focus to the element and sample while it is focused.
- **Active state (pressed):** hold the mouse button down on the element and sample before releasing.
- **Visited state (links):** follow a link to create a visited state, then return and sample.

**Expected result:** The text colour in every interactive state meets the applicable contrast threshold against its background in that state. State changes that alter text colour or background colour must still satisfy the same thresholds.

**Fail signal:** A hover state that lightens text colour below 4.5:1; a focus state that changes the background to a colour that reduces contrast with the text; a visited link colour that falls below 4.5:1 on the page background.

## 5 Pass / Fail criteria

| Step | Passes when | Fails when |
|------|-------------|------------|
| 1 Automated scan | Zero `color-contrast` violations, or all flagged items confirmed false positives | Any unresolved violation not cleared by manual testing |
| 2 Threshold determination | Every text element is correctly categorised as large or normal so the correct ratio applies | Large-text threshold applied to text that does not qualify, understating failures |
| 3 Normal text | Every normal text element is 4.5:1 or greater | Any normal text element falls below 4.5:1 |
| 4 Large text | Every large text element is 3:1 or greater | Any large text element falls below 3:1 |
| 5 Placeholder text | Every placeholder is 4.5:1 or greater (or 3:1 if large) | Any placeholder text falls below the applicable threshold |
| 6 Text over variable backgrounds | Worst-case contrast ratio at all sampled background points meets the threshold | Any sampled point along the text baseline falls below the threshold |
| 7 Interactive state text | Text colour in hover, focus, active, and visited states meets the threshold in each state | Any interactive state produces text below the applicable contrast threshold |

**Overall result:** The page **passes** SC 1.4.3 only when every applicable step passes.
A single step failure = **SC 1.4.3 failure**.

---

## 6 Common false positives

These situations can look like failures but are not:

- **Disabled form fields and buttons:** Text on elements with the native `disabled` attribute or `aria-disabled="true"` is explicitly exempt from SC 1.4.3. A greyed-out disabled submit button with low-contrast label text is not a failure of this criterion.
- **Logotypes:** Text that forms part of a brand logo or trademark is exempt. A company name styled as part of a logo in the page header does not need to meet 4.5:1.
- **Decorative text:** Text with no informational value that is purely visual in purpose is exempt. Assess carefully — if the text could be removed without loss of information or function, it may qualify.
- **Text inside images reported by axe as `color-contrast` violations:** Automated tools can misidentify image boundaries. Confirm by visually inspecting the element — if the text is part of a raster image, sample the actual rendered pixels rather than relying on the automated result.

These situations can look like passes but are not:

- **`#767676` on `#ffffff` appears borderline:** This combination produces 4.48:1 and is a failure. It is fractionally below the 4.5:1 threshold and is one of the most common errors to miss. Always check the exact ratio rather than estimating visually.
- **Text colour passes on the design's white background but the component sits on a different background in context:** A label designed against a white card may be placed inside a grey page section. Always sample the actual background the text renders against, not the design file background.
- **Automated tool reports a pass but the background is a gradient or image:** Automated tools often sample a single background point. A pass in the automated scan does not clear a text-over-image or text-over-gradient element — complete Step 6 for those cases regardless.
- **Hover or focus state text colour changed via CSS but not tested:** Interactive state colours are part of the criterion. A default state that passes does not guarantee that all interactive states pass.

## 7 Related criteria

Failures here often co-occur with failures in:

- **SC 1.4.6 Contrast Enhanced (Level AAA):** Requires 7:1 for normal text and 4.5:1 for large text. Not required for standard AA conformance, but useful to check for best practice where body text is concerned.
- **SC 1.4.11 Non-text Contrast (Level AA):** Covers the visual boundaries and state indicators of UI components (field borders, focus rings, icons). Contrast of non-text elements is not assessed under 1.4.3 — the two criteria together form the complete contrast picture for a component.
- **SC 1.4.1 Use of Colour (Level A):** If colour is used as the sole means of conveying information (e.g. red text for errors with no icon or label), a contrast failure and a 1.4.1 failure may co-occur. Assess both when low-contrast coloured text is found.
- **SC 3.3.2 Labels or Instructions (Level A):** Placeholder text that fails contrast (Step 5) is likely also being used as a label substitute, which independently fails 3.3.2. Raise both when placeholder contrast fails.
- **SC 2.4.13 Focus Appearance (Level AAA):** Defines minimum area and contrast requirements for focus indicators, stricter than the focus-state text contrast check in Step 7. Not required for AA conformance but useful context when testing focus states.
